# Evident Project Rules

When working in this repo:

- Do not implement before an approved spec exists.
- Prefer tight, demoable vertical slices.
- Keep the project credible for an early-career but unusually proactive data/automation engineer.
- Every feature should make the Evident relevance obvious.
- Public/synthetic data only unless explicitly approved.
- If using LLMs, include validation and clear failure handling.
- If scraping, respect robots/terms/rate limits and document assumptions.
- Optimize for a strong 2-5 minute demo to a product/data stakeholder.
